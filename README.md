# Cat Hop Rush

在线 Demo：`https://your-demo-url.com`

Cat Hop Rush 是一个竖屏 H5 跑酷小游戏。玩家点击屏幕让猫猫跳跃，躲开箱子，吃小鱼加分，并通过磁铁、护盾、双倍分数等道具冲更高分。

这个项目的目标不是做一个复杂的大型游戏，而是用前端常见技术把一个完整小游戏从 0 到 1 做出来：有游戏循环、碰撞检测、移动端适配、Canvas 绘制、音效、最高分、分享、道具、关卡感和性能优化。比较适合前端小游戏实习面试时展示。

## 项目亮点

- 原生 Canvas 实现核心玩法，没有使用 Phaser、Pixi 等游戏引擎。
- React 负责 UI 和状态组织，Canvas 负责高频绘制，职责比较清晰。
- 使用 TypeScript 定义游戏对象类型，比如猫、障碍物、小鱼、道具、粒子。
- 支持移动端竖屏适配，使用 `480x800` 虚拟设计尺寸等比缩放。
- 处理了高清屏 `devicePixelRatio`，避免 Canvas 在手机上发糊。
- 有道具系统、combo、关卡阶段、最高分、复制战绩和静音设置。
- 使用 Web Audio API 生成音效，不依赖外部音频文件。
- 增加低性能模式和开发环境 FPS 显示，方便移动端调试。

## 为什么用 React + TypeScript + Canvas

这个项目里我没有把所有东西都塞进 React 组件。

React 更适合做界面状态，比如开始界面、HUD、结束面板、静音按钮、FPS 开关。它的状态流比较清楚，也方便把游戏状态传给 UI。

Canvas 更适合做游戏画面。猫、鱼、箱子、粒子、背景云朵、地面速度线这些对象每帧都会变化，如果全部用 DOM 做，性能和控制感都不太好。Canvas 可以在一张画布里统一绘制，更接近小游戏开发的方式。

TypeScript 主要解决“游戏对象变多以后不容易乱”的问题。比如 `Fish`、`Obstacle`、`PowerUp`、`Particle` 都有自己的类型，后面加磁铁、护盾、combo 时，状态结构不会靠猜。

## 游戏循环

游戏循环封装在 `src/hooks/useGameLoop.ts`，底层使用 `requestAnimationFrame`。

每一帧会计算两帧之间的时间差 `deltaSeconds`，再把它传给 `updateGame`。这样移动距离是按时间计算的，而不是按帧数计算的。

简单说就是：

```ts
position += speed * deltaSeconds
```

这样 60 FPS 和 120 FPS 的设备上，游戏速度不会因为帧率不同而变快或变慢。

当前每帧主要做这些事：

- 更新猫猫跳跃和重力下落
- 移动障碍物、小鱼、道具和粒子
- 按时间随机生成障碍物、小鱼和道具
- 判断吃鱼、吃道具、撞箱子
- 更新分数、combo、关卡阶段和道具倒计时
- 清理移出屏幕或失效的对象

## 碰撞检测

碰撞检测使用 AABB 矩形碰撞，也就是判断两个矩形是否重叠。

核心逻辑在 `src/game/math.ts`：

```ts
a.x < b.x + b.width &&
a.x + a.width > b.x &&
a.y < b.y + b.height &&
a.y + a.height > b.y
```

项目里还有一个比较重要的处理：图片绘制尺寸和碰撞盒是分开的。比如猫猫图片会画得比碰撞盒稍大一点，看起来更自然；但真正参与碰撞的是较小矩形。这样可以减少“看起来没碰到却死了”的挫败感。

## 难度曲线

难度不是突然变高，而是慢慢增加。

项目里主要用了几层控制：

- 前 10 秒比较简单，给玩家适应时间。
- 分数越高，目标速度越高。
- 每 10 分进入一个新阶段，阶段越高速度略微增加。
- 高阶段会低概率出现双箱组合，但保留安全间距，避免无解。
- 障碍物高度和生成间隔都有随机性，但都有上下限。

速度不是直接跳到目标值，而是用插值平滑靠近：

```ts
speed = lerp(currentSpeed, targetSpeed, amount)
```

这样玩家能感觉到节奏在变快，但不会突然被难度“拍脸”。

## 移动端适配

游戏内部使用固定虚拟尺寸 `480x800`。所有游戏逻辑坐标都基于这个尺寸计算，比如猫的位置、障碍物位置、碰撞盒大小。

页面显示时再根据真实屏幕宽高等比缩放，并居中显示。这样不管是 iPhone 还是 Android，游戏逻辑都保持一致。

移动端还做了这些处理：

- 横屏时提示“请旋转手机竖屏游玩”
- 禁止页面滚动和双击缩放
- 支持 `touchstart`，点击屏幕任意位置都可以跳跃
- 使用 `visualViewport` 处理 iPhone Safari 地址栏变化
- Canvas 根据 `devicePixelRatio` 放大真实像素，高清屏不模糊
- 低性能模式会降低 DPR 和减少粒子，照顾性能较弱的手机

## AI 如何辅助开发

这个项目里 AI 主要参与了两类工作。

第一类是素材辅助。猫、鱼、箱子、背景这类图片可以先用 AI 生成，再放到：

```txt
public/assets/images/
```

Canvas 绘制时优先使用图片素材。如果图片还没加载完，游戏会用几何图形兜底，所以不会因为素材加载慢导致黑屏。

第二类是开发辅助。比如拆分代码结构、补充中文注释、梳理 README、设计道具参数、做性能检查，这些都适合让 AI 先给方案，再结合实际代码调整。

我对 AI 的使用思路是：让它提高开发效率，但核心逻辑仍然要能自己解释清楚。比如游戏循环、碰撞检测、难度曲线、移动端适配这些部分，都不能只停留在“AI 帮我写了”。

## 本地运行

安装依赖：

```bash
npm install
```

启动开发环境：

```bash
npm run dev
```

生产构建：

```bash
npm run build
```

预览构建结果：

```bash
npm run preview
```
